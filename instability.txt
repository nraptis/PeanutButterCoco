Bundle / Unbundle / Repair / Folder Compare instability notes

1. Operation lifecycle and UI state are still settling.
The UI now has Home / Ghost / Loading states, while the engine runs on a worker thread and emits events back to the app shell. This is improved, but the final ownership rules for prompts, orphaned events, stale responses, and mode switching during active work are not fully written down yet.

2. Director cancel policy is still under-specified.
The intended rule is "finish the current user file, then honor cancel, then finalize safely." The mock flow approximates this, but Bundle / Unbundle / Repair directors do not yet all expose the same explicit cancel boundary contract.

3. Repair is only partly distinct from Unbundle.
The engine now has a RepairDirector, but the exact salvage policy is still not fully defined: what gets skipped, what gets reconstructed, what should be logged as damaged, and when Repair should still fail hard instead of continuing.

4. Read Manifest is still a first-pass feature.
It now avoids the full decode path, but its output contract is still unstable. It currently trusts archive discovery facts and advertised preview-block counts more than decoded payload truth, and it does not yet have a final user-facing report format.

5. Public preview format is new and needs compatibility policy.
Preview blocks are now intentionally plaintext when "Include Preview" is enabled. What is still unstable is the compatibility story for:
- older archives that advertised preview blocks incorrectly,
- future preview payload schema changes,
- and whether preview presence should influence Unbundle / Repair behavior beyond reporting.

6. Unbundle source expectations still need one final rule.
It mostly works with a family folder, but the exact happy path is still not crisply declared:
- single archive file,
- folder of a full family,
- partial family,
- or mixed-content folder.
That ambiguity still leaks into logging, preflight expectations, and user guidance.

7. Bundle destination conflict policy is only implemented for the first prompt case.
The green / yellow / red light prompt flow exists, but the full matrix of destination conflicts is not finalized yet. In particular, merge semantics, overwrite semantics, hidden-file handling, and any nested conflict prompts need a single written rule set.

8. Folder Compare is functionally useful, but not yet fully productized.
Hidden-file warnings and capped mismatch examples are back, but the final product contract is still open:
- what counts as a warning vs a failure,
- how many examples to print,
- and whether there should be a machine-readable report output.

9. Portable Release behavior is now local-folder oriented, but not fully packaged.
Release builds are intended to run relative to the app's containing folder. Config can live alongside the app for portability, but packaging, signing, update behavior, and what else should live beside the app are still not fully defined.
